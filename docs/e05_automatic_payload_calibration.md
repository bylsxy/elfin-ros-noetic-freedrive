本文说明 Panel 中“拖拽高级 -> 高位一键标定未知末端”的用途、工作过程、安全边界和第一次使用方法。它标定的是拖拽重力补偿，不是相机外参，也不是夹爪 TCP。

## 1. 最终得到什么

标定数学本身不需要输入夹爪、剪刀、相机、转接件和线缆的单件质量或重心；程序把法兰之后牢固安装的全部物体视为一个等效刚性负载。运动安全另行强制读取当前 `harvester_tool.yaml` 的 STEP 派生包络，二者不能混淆。程序自动辨识：

- 总质量 `m`，单位 kg；
- 法兰坐标系中的三维重心 `[cx, cy, cz]`，单位 m；
- 拟合误差、独立留出姿态误差和短时零力保持漂移；
- 候选短时保持姿态占用的每轴力矩容量，以及完整标定路径的诊断峰值。

空臂本体仍使用已经完成的多姿态基础重力模型。新增末端只作为独立负载力矩叠加，不会污染原来的空臂 J2/J3 标定。

成功配置默认持久化到：

```text
/home/catas/.ros/elfin_freedrive_payload.yaml
```

每次标定的原始双向样本和候选结果保存在：

```text
/home/catas/.ros/elfin_payload_calibration_runs/YYYYMMDD-HHMMSS/
```

只要当前版本的 7 组样本采集完整，程序就会先写入只读测量报告：

```text
measurement_report.yaml
```

“测出了质量/重心”和“该模型可以安全启用 FREE”是两件事。即使重心范围、短时保持姿态容量或其他控制审查不通过，报告仍会保留测得的质量、重心、拟合误差和拒绝原因；正式负载配置保持不变。完整标定路径的容量峰值也会记录，但这些姿态是在位置控制器承重时用于激励辨识，不再错误要求每个激励姿态都必须允许进入 FREE。只有当前短时保持姿态的 88% 余量审查和最长 1 秒保持验证全部通过后，才会生成并启用正式候选。

## 2. 为什么不靠自由下坠标定

主体辨识始终由普通位置控制器承重。机械臂默认以 `5%` 速度和 `5%` 加速度到达多个姿态，静止 `0.80 s` 后采集 `0.60 s` 编码器角度和电机反馈力矩。程序不会松抱闸，也不会通过观察坠落距离来猜重力。

对每个姿态，机械臂会从两个相反方向到达目标附近，再平均两次反馈力矩。减速器回差和位置控制容差会让两次真实编码器角度略有差异，因此程序分别按各自的真实角度计算重力基线和负载回归矩阵，再平均模型项；双向位置差只写入日志，不作为重复的退出门限。这样既减弱减速器静摩擦方向对结果的影响，也不会把正常回差误判成故障。回归参数是：

```text
[m, m*cx, m*cy, m*cz]
```

5 个姿态用于拟合，另外 2 个未参与拟合的姿态用于独立检查。姿态集覆盖低/中/高肩肘负载、腕俯仰正负、腕滚转正负，并把实际工作区 `J2/J3≈0.75/-0.76 rad` 作为留出姿态。只有刚性负载模型能同时解释留出姿态时，候选才会继续进入短时保持验证。

回归首先计算无约束解。如果位置控制的关节零偏使无约束结果出现物理上不可能的负质量，程序不会把负数硬改成某个正数，而是投影到刚性负载可行域的空负载边界（`0 kg`、零重心），再用全部拟合与留出姿态检查这个零模型。当前确实为空法兰时可以正确得到空负载；实际装有负载时，零模型无法解释各姿态新增的重力力矩，仍会因残差超限而拒绝。

## 3. 一键流程实际做什么

点击按钮并通过清场确认后，程序按下列顺序工作：

1. 检查最新六轴、Servo On、无 Fault、位置控制器和 FREE 管理器状态。
2. 要求当前法兰不低于 `z=0.45 m`，活动连杆不穿 `z=0`，当前 STEP 包络最低角点不低于 `z=0.30 m`。
3. 要求 `harvester_tool.yaml` 已通过 STEP 几何和执行核验，并确认其中全部 18 个保守子包络已附着到 `elfin_end_link`；每个候选状态都把这些 attached collision objects 一并送入 MoveIt 状态有效性检查。
4. 完成 5 个拟合和 2 个留出姿态的双向靠近、静止和采样，共约 29 段 `5%` 位置运动；每完成一组就原子更新原始样本 CSV，后续失败也保留已完成数据。
5. 用 5 个姿态拟合质量和三维重心，用 2 个留出姿态检查模型。
6. 拒绝质量、残差或当前短时保持姿态力矩容量超限的候选；完整标定路径容量作为诊断写入报告。
7. 先暂存候选，不写入正式文件；将六轴验证阻尼提高到至少 200%。
8. 进入最多 `1.00 s` 的重力补偿保持，默认 `0.80 s`；漂移或速度超限会提前结束，独立看门狗也会在 1 秒请求退出。
9. 退出 FREE 并确认重新回到位置保持，恢复标定前阻尼。
10. 仅在全部通过后原子写入正式负载 YAML，再返回标定前姿态。

候选暂存期间只有自动标定器可临时忽略“位置模式反馈与模型的逐轴绝对差”；该数值会受减速器静摩擦和预靠近方向影响。它仍写入日志，但真正的候选验收由多姿态拟合、留出误差、当前保持姿态 88% 容量余量和最长 1 秒的实际漂移/速度共同完成。保持成功后正式文件写入 `hold_verified: true`，普通 FREE 才会把该绝对差降为诊断，并允许从未验证负载的 90% 容量线进入 92% 窄迟滞带；以 J3 36 Nm 显式限值计仍保留 2.88 Nm。失败回滚不会继承这个标记。Servo/Fault、方向、关节限位、碰撞、速度和绝对力矩限制不受影响。

任一步失败或按下“中止标定”，脚本都会请求停止 MoveIt 轨迹、退出 FREE、等待 `READY`、恢复旧负载并恢复原阻尼。Panel 的 Stop、Servo Off 和上游电闸始终保留为独立停止路径。

## 5. “未知”不等于“任意情况都保证安全”

任何软件都无法对完全未知的实体外形、松动零件、任意偏心 5 kg 负载和柔性线缆给出绝对安全保证。当前防线有明确边界：

- MoveIt 状态检查必须同时携带当前 18 个 STEP 派生 attached collision objects；任一对象缺失或附着连杆不是 `elfin_end_link` 都会拒绝。当前包络还会独立做 `z=0.30 m` 角点硬门禁，机械臂活动连杆做 `z=0` 硬门禁。
- MoveIt 和 STEP 包络仍看不到人员、桌面上未加入场景的物体、松动零件或包络外新增线缆。`z=0` 上方无障碍是现场前提，不是软件从传感器推断出来的事实。
- `5 kg` 是质量上限，不代表任意 5 kg、任意重心都满足每个姿态的轴力矩上限。重力力矩取决于一阶矩 `m*c`，固定重心距离会误拒绝轻质长工具，因此 `0.60 m` 只作为扩展距离提示。FREE 输出上限来自 E05 URDF 六轴额定力矩 `[420, 420, 200, 200, 69, 69] Nm`，不再叠加历史 20% 或人工逐轴帽；候选仍必须通过拟合/留出残差、实际短时保持姿态的 88% 额定容量余量和最长 1 秒保持。
- 位置运动期间由位置控制器和底层驱动保护。位置控制的加减速/摩擦反馈力矩只记录峰值，不再错误套用 FREE 输出门限；Servo/Fault、状态过期、轨迹跟踪和 MoveIt 检查仍会停止流程，底层 Fault 不能被本脚本绕过。
- 静态采样以整个采样窗的编码器实际位置跨度判断是否移动。驱动 `joint_states.velocity` 的孤立毛刺会连同同期位置跨度写入日志和 CSV，但不会在编码器事实上没有移动时误杀标定。
- 柔性线缆随姿态变化的拉力不能由一个固定重心精确表示。若它使留出姿态残差过大，标定会拒绝；若线缆以后重新布置，必须重新标定。
- 法兰之后增减夹爪电机、摄像头或工具属于末端负载变化，可以重新运行本标定。若改动的是机械臂本体连杆、关节电机、减速器或编码器，则空臂基础模型也变了，不能只做末端负载标定。
- 抓起水果后负载又发生变化。正式采摘程序应按“空夹爪”和“已夹持典型果实”分别管理负载，不能假设一次标定永久覆盖所有抓取状态。

## 6. 如何判断成功或失败

成功时 Panel 过程窗口最后会出现：

```text
[启用] 已验证并持久启用：...
[完成] 自动末端负载标定全部通过；下一次 FREE 使用新配置
```

常见拒绝原因：

| 提示 | 含义 |
| --- | --- |
| 法兰低于 `0.45 m` | 先用普通位置点动移到满足法兰门限的姿态 |
| STEP 包络角点低于 `0.30 m` | 当前真实末端净空不足；不得降低门限，先人工抬高或调整姿态 |
| STEP 派生子包络未全部附着 | 当前 MoveIt 状态无法覆盖真实末端碰撞；修复附着后再运行 |
| MoveIt 碰撞检查失败 | 预设姿态或路径与当前机械臂/附着末端/场景冲突，程序不会执行 |
| 候选保持姿态力矩容量超限 | 当前准备进入短时 FREE 保持的姿态已接近命令饱和，拒绝进入保持 |
| 标定路径诊断峰值高于 88% | 某个位置控制激励姿态不适合 FREE；不单独拒绝候选，运行时 90% 门禁仍会阻止在该姿态继续拖拽 |
| 留出姿态误差过大 | 末端松动、线缆拉扯、摩擦异常或负载不能近似刚体 |
| 质量大于 5 kg | 超过当前 E05 铭牌额定负载，直接拒绝 |
| 保持漂移或速度超限 | 候选重力补偿不能稳定承重，自动退出并回滚 |
| Servo/Fault 状态过期 | 驱动状态超过 0.75 s 未更新，不能继续 |
| 持久化失败 | 正式 YAML 未替换；消息会分别报告写入原因和控制器回滚结果 |

失败后先区分测量质量与控制门禁，不得把人工软件帽造成的控制拒绝误判成测量失败。不要修改 URDF 厂家额定力矩、碰撞、高度、Fault 或运动保护来掩盖真实问题；应先检查门限来源、末端紧固、线缆走向、实际总质量、机械接触和原始样本。

2026-08-11 的 `auto-payload-20260811-071430` 即为反例：测量质量完全通过，J5 预测需求为 `9.411 Nm`；旧 `10 Nm` 人工帽把它换算为 `94.1%` 并反复拒绝，而相对 J5 URDF `69 Nm` 额定值仅占 `13.64%`。该失败纯属历史门禁配置，不是用户从 Home 启动、标定运动或负载辨识错误。

若日志已经显示当前版本 `7/7`，不要重复运动。可以直接对保存的 CSV 做只读复算：

```bash
source /opt/ros/noetic/setup.bash
source /home/catas/ros_ws/devel/setup.bash
rosrun elfin_freedrive_controller calibrate_elfin_payload.py \
  --analyze-samples /home/catas/.ros/elfin_payload_calibration_runs/YYYYMMDD-HHMMSS/static_pairs.csv
```

这个入口只调用基础重力/末端回归矩阵查询服务并写报告，不发送 MoveIt 轨迹，不进入 FREE，也不修改负载配置。报告中的 `measurement_valid` 表示数据能否支持刚性负载测量；`eligible_for_control_hold_test` 表示保存样本的末尾高位姿态能否继续参加真实 FREE 短时保持验证。报告同时保留完整标定路径的容量诊断，两者不要混淆。

若报告显示当前版本 7 组样本完整、`eligible_for_control_hold_test: true`，并且末端和线缆自采样后完全没有改变，可在 Panel“拖拽高级”点击“复用最近样本，仅做短时验证”。Panel 会过滤旧 8 姿态样本，只接受姿态名称与当前 7 姿态版本完全一致的 CSV。复用时重新检查 attached STEP 包络、当前姿态高度、Servo/Fault、保持容量和静态力矩一致性；当前姿态违反法兰 `0.45 m` 或包络 `0.30 m` 门限时直接拒绝，不会从低净空起点自动运动。

## 7. 与相机、TCP 和触碰凹点标定的关系

正确顺序是：

```text
安装/修改末端
  -> 自动负载与重心标定
  -> 小范围验证 FREE 手感
  -> TCP/夹爪几何标定
  -> eye-to-hand 相机外参标定
  -> 深度障碍与采摘规划验证
```

POINT 记录的是六轴关节姿态，可作为 TCP 或 eye-to-hand 样本索引。用固定凹点从多个方向触碰，可以求工具中心点；相机标定还需要对应的视觉观测。两者以后可以由同一个向导组织，但不能与未知负载辨识混成同一个数学问题，也不能在负载标定之前依赖尚未确定的 TCP。
